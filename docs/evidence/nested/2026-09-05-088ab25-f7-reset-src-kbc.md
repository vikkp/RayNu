## What this run adds over `fe4785a`

`fe4785a` reached reboot-to-disk but the two reset lines were dropped (blocking
`serial::write_str` while Linux earlycon share was on). `088ab25` prints them via
the nowait path and leaves share mode before the relaunch banner. Both now appear:

```
924:boot: RayNu-F guest reset requested src=kbc n=1 (F7; not ISO-INSTALL-OK)
925:boot: RayNu-F relaunch after reset (F7; not ISO-INSTALL-OK)
```

**Reset source observed: `kbc`** — Alpine's `reboot` (busybox → kernel
`machine_emergency_restart` → `native_machine_emergency_restart`) pulsed the
i8042 output port (`0x64 <- 0xFE`), not `0xCF9` and not the FADT
`RESET_REG`. Linux boots here with `efi=noruntime`, so `EFI_RESET_SYSTEM` is
out and the kernel falls through its `reboot_type` ladder (KBD first on this
path). `0xCF9` and triple-fault classification remain host-tested only.

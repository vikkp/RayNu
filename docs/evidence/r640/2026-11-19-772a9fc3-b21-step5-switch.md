# Gate 2 step 5 on `772a9fc3` — stop of slot 1 restarted slot 0

EFI `772a9fc3b220`, run `44639854905`. COM2 after Stop of Alpine (slot 1)
while Ubuntu (slot 0) was at `raynusrv2 login:`:

```
RAYNU-V-AUDIT: VmStopped guest_id=1
boot: guest slotboot: guest-UEFI restore host xcr0=0x1 osxsave=0 reason=0x34 rip=0xffffffff99f3ef7d
boot: SPA stop idle — guest off; Start on that row boots it again
RAYNU-V-AUDIT: VmStarted guest_id=0
boot: guest slot 0 boots again guests_on=0
```

The beat immediately before that stop was `guests on=2` with
`cores 0:[0.0 1.0] 1:[0.1] 2:[1.1]`.

## What the source does

`on_guest_left` (`vmx/guest_sched.rs`) prints `VmStopped` for `slot::current()`,
then switches to `first_on_except`. The unit it passes is

```text
slot::unit(next, slot::with_slot(next, slot::current_vcpu))
```

`current_vcpu` is `CUR_VCPU[slot]` (`guest/slot.rs`). `switch_in` stores that
word for whichever vCPU it enters (`vmx/guest_sched.rs`, `set_current_vcpu`).
Core 1 had entered Ubuntu's vCPU 1 (`B21 vcpu 1 on host core 1`), so
`CUR_VCPU[0]` was 1. That unit is assigned to core 1. `switch_in` returns
false when `vmptrld` fails (`vmx/guest_sched.rs`). A VMCS still active on
core 1 fails `VMPTRLD` on core 0.

The failure branch then runs `slot::set_on(next, false)` and returns.
`leave_to_e4` (`vmx/guest_uefi.rs`) only reaches `SPA stop idle`
(`vmx/launch.rs`, `enter_spa_stop_idle`) when `on_guest_left` returns. The
success path calls `enter_guest` and does not return. `guests on=2` means
`next` was slot 0, so the return is that failure branch.

`home_unit_for` is specified in `docs/plans/b21_plan.md` (section 5g and
WP10) and is not in the tree. vCPU 0 of slot 0 was assigned to core 0
(`I4` in `arch/host_smp.rs`). Naming that vCPU before `switch_in` is the
load that stays on this core.

## Correction

The pasted COM2 does not contain the nowait line
`guest switch failed: VMPTRLD refused the remaining guest's VMCS`. The bytes
there are torn (`boot: guest slot` run into the xcr0 restore). The control
flow above is what the lines that did survive require.

`guest slot 0 boots again` is `launch` with `start.auto` set
(`vmx/guest_sched.rs`). That flag is `AUTO_RESTART` of the slot being
started. Operator Stop takes `Leave::StayOff` (`leave_plan`) and does not
store `AUTO_RESTART`. The idle loop could start slot 0 only after the
failure branch had cleared `ON[0]`. The Stop arm itself did not store
slot 0's restart latch.

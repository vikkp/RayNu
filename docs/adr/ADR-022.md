# ADR-022: One guest model, N guest slots

- **Status:** Accepted. Built on branch `cursor/wave-7-b6-seats-37d7`. Lived on the R640 on 2026-11-17 (`4f581a4dcd93` / run `44174137515`): two product guests ran side by side (ADR-021 B6).
- **Date:** 2026-11-17
- **Pillars:** [Z] single binary · [V] architecture (explicit per-guest state, no second code path) · [A] every slot's VMCS is audited
- **Parent:** [ADR-021](ADR-021.md) rows B6 and B7 · [ADR-020](ADR-020.md) (RayNu VM Generation 1) · [ADR-016](ADR-016.md) (RayNu-F)
- **Does not change:** Proven Core boundary (ADR-002). `sched/msr_firewall.rs` and `audit/integrity.rs` are not edited. No guest firmware state is forced (ADR-016).

## Context

B6 is "more than one product guest at once on one R640". The first attempt added a **seated** second guest: a second VMCS with its own copy of the firmware services, the PCI walk, the UART, the PIT, the local APIC and the virtio queue, each written again beside the first guest's. Thirty iron flashes moved that copy from a double fault to GRUB to a Linux banner (`767261a7`), one missing device at a time. Every flash found the next thing the copy did not have.

That path does not end. The first guest boots Alpine and Ubuntu because its machine model was earned on iron over months. A second, smaller machine model has to earn all of it again, and again for every distribution, and again for Windows. The operator would also get two kinds of guest: one that works and one that mostly works.

The seated copy was removed in `c5e0b719`.

## Decision

**There is one guest machine. A second guest is a second instance of it, not a second implementation.**

1. **Guest slots.** `guest/slot.rs` names the slot the CPU is serving (`current()`), with `MAX_GUESTS = 4`. All product-guest state (the exit path's flags and saved registers, RayNu-F, every device model, the management plane's per-guest records) lives in `PerGuest<T>` / `PerGuestCell<T>` banks with one entry per slot. Code that reads a guest static reads the current slot's entry. The exit handlers, the devices and RayNu-F do not know how many guests there are.

2. **A slot is a whole machine.** Each slot has its own VMCS, EPT, 32 MiB low-RAM slab, flash image, report RAM, MMIO scratch, I/O and MSR bitmaps, GDT and TSS, I/O APIC, local APIC page, HPET, PIT, UART, virtio-blk and virtio-net state, and SMBIOS credential. Slot 0 is built at boot as before. Slots 1–3 are built on the first Start that needs them (`build_slot_machine`), entirely from the leftover-DRAM bump, and are never freed. A build that cannot finish is refused with a line on COM2, and the running guest keeps the CPU.

3. **One launch path and one exit path.** A slot is launched by the same `raynu_f_launch_on_stopped_vmcs` and exits through the same `raynu_f_vmexit` as slot 0. Every slot exits onto one shared host stack, because one guest is in VMX non-root at a time.

4. **The guest scheduler (`vmx/guest_sched.rs`).** At the end of every VM exit the exit path calls `guest_sched::resume`. With one guest on, that is `VMRESUME`. With more than one, a pure policy function (`pick`) chooses: a busy guest keeps the CPU for a 2 ms quantum, then the slots are asked round-robin; an idle guest (HLT with nothing to inject) gives the CPU up at once; a halted guest with no known work still runs every 10 ms. The VMX preemption timer bounds the quantum.

5. **What a switch carries.** The VMCS holds RIP, RSP, RFLAGS, segments, control registers and DR7. The scheduler saves and loads the rest: the general registers, the full XSAVE image under the host's whole XCR0 mask, XCR0, CR2, DR0–DR3, DR6, `STAR` / `LSTAR` / `CSTAR` / `SFMASK` / `KERNEL_GS_BASE`, `TSC_AUX`, and the two shadowed MSRs (`SPEC_CTRL`, `APIC_BASE`). It issues an indirect-branch barrier when the CPU has one. A guest never enters with another guest's values. A guest that is booted into a used slot starts from reset values.

6. **Disk.** A slot is bound to the span of RAYNU-SPARE it was started on (`bind_perc_span`): the 8 GiB window, or a catalog row's offset and size. Two guests never share a span. A Start of a row that is already on answers `running` and starts nothing. A Start with every slot in use answers `busy`.

7. **Console.** There is one COM2. The guest the operator started last owns it and is written as before. Every other guest's output is collected per slot and written as whole lines with a `[gN] ` prefix. Typed input goes to the owner.

8. **Uplink.** There is one guest uplink (BCM5720 function 1). With one guest on, every received frame is posted to that guest, as before. With more than one, frames are split by destination MAC (the address in the guest's device config, or the address it last sent from); broadcast and multicast go to every guest with a NIC; a frame one guest sends to another is posted directly and does not go to the wire. This is not the M4 vSwitch.

9. **Lifecycle is per slot.** Stop, Shut down and Reboot name a catalog row and act on that slot. An untargeted Stop with more than one guest on is refused (409) and no guest is stopped. A guest that leaves the CPU on its own while another is on is booted again once for each operator Start; after that it is marked off.

10. **Timers follow the guest, not the wall.** A guest that was off the CPU when its timer tick came due gets the tick when it next runs. Watchdogs that ask "has this guest been quiet" count the guest's own time on the CPU.

### What this keeps open

- **Any Linux.** Nothing in the slot, the scheduler, the console split or the uplink split knows what the guest is. A distribution that installs and boots as the only guest installs and boots in a slot, from the same media, through the same firmware and devices. What a distribution needs from the machine itself is [ADR-020](ADR-020.md), and each fix there reaches every slot because there is one machine.
- **Windows.** The switch carries what Windows uses and Linux does not: the full extended state including components the previous guest never enabled, the debug registers, `KERNEL_GS_BASE` and the syscall MSRs, and a per-slot local APIC and I/O APIC. Windows needs UEFI runtime services and a variable store (ADR-020 phase 3) and, in practice, more than one vCPU (B7). Neither is built here. Neither needs a change to the slot model.
- **Multi-vCPU (B7).** `current()` becomes per physical CPU and a slot gains more than one saved context. The banks do not change.

## Consequences

- **Lived on iron `4f581a4dcd93`** ([evidence](../evidence/r640/2026-11-17-4f581a4d-wave-7-b6-two-guests-ok.md)). Ubuntu was at its login. Start of the Alpine row on Guests built slot 1 on its own span of the spare (`spare_off=8589934592`), and Alpine booted to `localhost login:` through the same RayNu-F path. COM2 printed `boot: guests on=2` five times with both `runs=` counts moving. `ssh` to Ubuntu answered with both on. Stop on the Alpine row left `1 guest(s) still on`.
- **Nested QEMU** (`TWO_GUESTS=1 ./tools/run-qemu.sh`) covers what iron did not: two guests installing at once, a guest powering off through the ACPI ask while the other runs, and a second Start of the same slot from the same disk. Nested is not iron.
- **Same boot, operator report.** The Alpine row was started again and reached `localhost login:`. Shut down on that row completed. COM2 for those two steps was not pasted.
- **Not run on iron yet:** two guest NICs at once (the Alpine guest had no vNIC, so the split by destination MAC has run in host tests only).
- **Two older faults showed up only with two guests, and are fixed for every guest.** A SysRq BREAK from the installer watchdog could land in front of typed input, so the next typed byte was taken as the SysRq key. The ACPI SCI line was raised for a power ask and never lowered; on the I/O APIC (B8) that is an interrupt storm (`soft lockup ... irq/9-acpi`). B4 lived on the 8259, where one raise is one interrupt. IRQ 9 now goes low when the guest clears the button status. Shut down on the I/O APIC has not been re-run on iron.
- **Memory is fixed at build.** Slot 0 keeps the report RAM it was granted. A later slot gets up to the same amount from what is left and is refused under 448 MiB. A slot's machine is not returned when its guest stops; the next Start reuses it.
- **A Start is not free for the running guest.** The operator's Start of a slot zeroes that slot's report RAM before entry so a new guest cannot read the previous guest's memory. The running guest is off the CPU for that time (about a second per 2 GiB).
- **One CPU.** Two busy guests each get half of one core. That is what B7 and the scheduler rows are for.
- **One console.** A full-screen installer is usable only on the guest that owns COM2. The second guest's console is readable, not interactive, until per-guest consoles (C-row) exist.
- **The Proven Core is unchanged.** The scheduler, the slots and the device banks are outside it. The MSR firewall's shadow is read and written through its existing interface.
- Scores stay put. HDA overall stays 99%. B6 stays `in flight` until COM2 on the R640 shows both guests running.

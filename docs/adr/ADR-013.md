# ADR-013: Management Network Architecture

- **Status:** Accepted
- **Date:** 2026-08-17
- **Pillars:** [Z] [D] [A] (Proven Core **[V] unchanged** — network code stays
  outside the verification boundary unless a future ADR expands ADR-002)
- **Parent:** [ADR-009](ADR-009.md) (Mount Everest) · [ADR-012](ADR-012.md)
  (PRE-EBS UEFI HTTP) · size: [ADR-003](ADR-003.md) · iDRAC: [ADR-005](ADR-005.md)
  · Proven Core: [ADR-002](ADR-002.md)

## Context

RayNu-V serves a management HTTP interface (SPA + REST) over a UEFI SNP +
smoltcp residual. That path works only in a short **PRE-EBS** window
([ADR-012](ADR-012.md) / M7.6 / `RAYNU-V-M7-UEFI-HTTP-OK`, iron 2026-08-16).

For the hypervisor to be an operator product, the management plane must remain
available for the **lifetime of the host**, not for 45 seconds before
`ExitBootServices`.

Iron on Cruzer (BIOS 2.2.11, 2026-08-17) falsified the hidden ADR-012
assumption that parking SNP across EBS would yield a durable listen:

1. First `iface.poll` immediately after EBS **never returned**.
2. Skip-immediate-poll: guest path green, then idle SNP after `BOOT-OK` —
   Mac curl timed out; Dell UEFI **RSOD** (invalid opcode, RIP=`0x17`).

Evidence: [`docs/evidence/r640/2026-08-17-post-ebs-snp-dead.md`](../evidence/r640/2026-08-17-post-ebs-snp-dead.md).
PR #157 makes post-EBS SNP **WARN-only**. Firmware Tcp4 was already a
platform limit on this boot method.

We need an architecture that:

- Removes the 45-second race **without** calling firmware network protocols
  after EBS
- Stays faithful to the single-binary philosophy ([Z])
- Does not undermine the Proven Core ([V] / ADR-002 / ADR-004)
- Has an explicit threat model

## Decision

Two stages — **bring-up (done)** vs **lifetime (this ADR)**. Stage 1 is
**not** “park SNP forever.”

### Stage 0 — Bring-up (done; keep)

Continue using the existing SNP + smoltcp residual **before**
`ExitBootServices` only. This is HDA **E3** MVP. Do not extend it across
EBS. After EBS: no `Tcp4` / `Snp` / `Mnp` / `Dhcp4`, no `locate_handle` /
`stall` / `CloseProtocol`. Soft-fail (serial WARN) if someone expected
lifetime SNP.

### Stage 1 — Native lifetime stack (target)

The hypervisor owns a **minimal native NIC driver** + **smoltcp**. The
existing `handle_http_request` codec runs on top of that stack for the
lifetime of the host. This is HDA **E3b** (durable mgmt). Everest does
**not** close on Stage 0 alone.

### Stage 2 — Future, not v1

Move the management stack into a tightly constrained service VM with its
own EPT context, talking to the Proven Core only through narrow hypercalls.
That turns today’s module + arena boundary into hardware-enforced isolation.
Not required to accept this ADR or to close E3b.

### Key decisions locked

**smoltcp only.** We will not write a custom TCP/IP stack. Only the
`smoltcp::phy::Device` implementation (NIC driver) is custom. Pin the
smoltcp crate version (same spirit as ADR-008 toolchain pins).

**In-binary, single address space for v1 ([Z]).** No helper OS, sidecar, or
second binary. No service VM yet.

**Firmware protocols forbidden after EBS.** Lifetime HTTP is host-owned
MMIO + DMA. Do not reuse `RAYNU-V-M7-POST-EBS-HTTP-OK` (SNP-era name).
New iron marker (when an exchange lands on the native stack after
`BOOT-OK`):

```text
RAYNU-V-M7-HOST-NIC-HTTP-OK
```

Host/CI may print only a scaffold marker (`RAYNU-V-M7-HOST-NIC-SCAFFOLD-OK`)
until that iron line exists. Slice: **M7.8**. Do not reopen M7.6.

**QEMU first, then one R640 chip.** Lab backend is QEMU `e1000` (or
equivalent user-net device). Iron backend is **one** PCI `vid:did` chosen
from a PRE-EBS census (BARs, MSI-X cap, IOMMU on/off). Census closed on
R640 2026-08-17: **`14e4:165f`** (BCM5720 dual-port). Iron 2026-08-18:
SNP DHCP is **`01:00.1` / `:5a:3a`**; do not bind func 0 (`:5a:38`) —
that port has no LAN ARP. Do not start X710/i40e. Evidence:
[`docs/evidence/r640/2026-08-17-phase0-census.md`](../evidence/r640/2026-08-17-phase0-census.md).

**Poll-mode MVP.** No MSI-X until a later slice. Any polled driver runs
with a **bounded poll budget** so it cannot starve the credit scheduler.
Acceptance: under synthetic load, polling must not cause measurable vCPU
scheduling degradation beyond an agreed threshold (recorded when the lab
harness exists).

**Dedicated mgmt arena (required, not a detail).** The management plane
uses a fixed-size allocator/arena **distinct from the Proven Core frame
allocator**. “Outside Proven Core” means **code and heap**. See Appendix A.

**Mgmt fatals are `Result`, not Rust panic-abort of the BSP.** Proven Core
keeps `panic = abort` (ADR-003, no unwind tables). The management loop
must be restartable: on `MgmtFatal`, drop the arena, watchdog reallocates,
listen again. Do **not** use `catch_unwind` (rejected — Appendix A). Do
**not** claim “a Rust panic in the driver leaves guests running on the
same hart” — that is Stage 2.

**Unsafe containment.** All `unsafe` for the NIC driver and ring buffers
lives in a **single module**. That module is subject to **Miri + fuzzing
on mocked DMA / packet parse paths** before it is production-ready. Miri
does not execute real MMIO; iron link-up is a separate box.

**NIC separation.** **Locked (operator 2026-08-19):** iDRAC NIC Selection =
**Dedicated** (rear dedicated RJ45). Host mgmt Ethernet on a BCM5720 LOM
jack, not the iDRAC dedicated port. Do not use Shared LOM / Shared with
Failover for iDRAC. Runbook:
[`docs/runbooks/r640_idrac_dedicated.md`](../runbooks/r640_idrac_dedicated.md).
Sharing a LOM with high-volume guest virtio-net is still a Phase G note.

**Auth / TLS.** Phase 0–D (now through first native HTTP): trusted-LAN
only. Bring-up token or ESP `auth.token` is sufficient. No TLS required.
Before any wider exposure: TLS + proper authentication become mandatory
(ADR-003 size still binds).

**Reuse the HTTP codec.** Do not fork a second HTTP implementation.

## Threat model (explicit)

**Trust boundary:** anything arriving on the management NIC is untrusted.

Because v1 is single-binary at VMX root, a memory-safety or logic bug in
the HTTP parser, TCP reassembly, or driver can give an attacker the host.
Formal proofs about EPT exclusivity (ADR-004) **do not** protect against
this class of attack.

Mitigations for v1:

- Network code remains outside Proven Core (ADR-002).
- Aggressive safe Rust; minimized `unsafe` in one module.
- Fuzzing and Miri on the driver/packet path (mocked DMA).
- Restartable management loop with a dedicated arena (Appendix A).
- Operational requirement: isolated management network / VLAN.

## Consequences

### Positive

- Names lifetime HTTP as a first-class Everest box (**E3b**) without
  revoking the PRE-EBS E3 win.
- Keeps the design single-binary.
- Avoids verifying a TCP/IP stack.
- Makes the threat model and residual risks explicit.
- Stops spending engineering on firmware SNP after EBS.

### Negative / accepted risks

- v1 still has a large TCB at VMX root (the management plane).
- A serious bug in that plane can still compromise the host.
- Hardware-enforced isolation of mgmt is deferred (Stage 2).
- Native NIC work is M2-class device risk; Everest months must reflect
  that, not a “park SNP” leftover.

### Neutral

- PRE-EBS SNP remains the bring-up UI (optional); durable HTTP is native BCM5720 after `BOOT-OK` (E3b closed 2026-08-20).
- El Torito, guest console UI, TLS, and a real distro installer remain.

## Appendix A — Panic and allocator isolation

The Stage 1 stack sits next to VMX/EPT in the same binary. Without
allocator separation, a memory-safety bug in ring-buffer `unsafe` has a
plausible path into Proven Core frame-allocator metadata. At that point
“network code stays outside Proven Core” would be true of **where files
live**, not of **what they can corrupt**.

**Adopted:** abort-the-**mgmt-loop** and respawn with a dedicated arena.

- Management gets its own fixed-size arena at init, separate from the
  Proven Core frame allocator and from guest-exclusive slabs (ADR-004).
- On `MgmtFatal`: drop sockets, re-init the arena, respawn listen.
  In-flight TCP/HTTP state is lost (acceptable for mgmt; not a guest-facing
  pattern).
- HV-wide Rust `panic = abort` remains. Containment is **engineered
  `Result` + arena reset**, not `catch_unwind`.

**Rejected:** shared allocator + `panic = "unwind"` / `catch_unwind`.
Unwind tables fight ADR-003. Catching a panic says nothing about whether
shared allocator state was already corrupted.

**Observable check (Phase E):** after N consecutive induced fatals,
Proven Core allocator metadata (or equivalent accounting) is unchanged
via the existing debug/introspection path. Host test:
`mgmt/mgmt_arena_test.rs` (`induced_fatals_do_not_touch_frame_allocator`).
Firmware listen scratch is allocated from `MgmtArena` (64 KiB `.bss`);
on `MgmtFatal` the loop resets the arena, records `AuditEvent::MgmtRestarted`,
and retries. HV-wide `panic = abort` is unchanged.

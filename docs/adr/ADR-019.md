# ADR-019: Guests screen is the spare boot policy

- **Status:** Accepted
- **Date:** 2026-09-28
- **Pillars:** [Z] single binary · [A] audit ([V] architecture preserved — no Proven Core expansion)
- **Parent:** [ADR-014](ADR-014.md) (typed ISO) · [ADR-018](ADR-018.md) (M8) · [ADR-009](ADR-009.md) (Everest, closed)
- **Rollback:** GitHub [`v0.1.0-m8-perc-spa`](https://github.com/vikkp/RayNu/releases/tag/v0.1.0-m8-perc-spa) (not Latest). EFI source `8ad2ac89125e`, CI `36362775808`, COM2 `build: sha=8ad2ac89125e`, SHA256 `6d5dc7cbe088182b6dcd7896717f1cb204ba2e3604f477404ef0b809349c6849`.

## Context

`8ad2ac89` lived both SPA paths on the first 8 GiB of RAYNU-SPARE. Choice 2 reinstalled that window (`d43dbf07-…`). A later boot, choice 1, reached `localhost login:` from that UUID with `setup-disk` withheld. The Overview buttons were a lab gate for one Alpine image. The Guests page already has the ADR-014 fields (CPU, RAM, disk, `linux_iso`) and they do not look at the spare. A new browser shows "No guests" while that Alpine is running, because the list is browser memory of `POST /vms`.

The 8 GiB constant is the copied Toshiba window. RAYNU-SPARE is about 2.9 TB. UBUNTU0 (~400 GB, Ubuntu 26.04) is the standing OS. The H840 stays unmapped. The read-only whole-VD virtio (`vdc`) stays hidden while the image latch is set.

Unmodified media was 20% when this ADR was accepted: an Alpine ISO patcher plus a serial auto-answer. Slice 3 on `752586b9` moved it to 25% by withholding `setup-disk`. The file that booted was still `EFI/RayNu/linux.iso` on the Cruzer. Decision 9 is how the operator chooses a later file.

## Decision

1. **Guests is the install and boot control.** When the spare image is latched, the firmware scans that latch, publishes one guest row, and waits. Start on that row boots it with `setup-disk` withheld. Create with `linux_iso` is the install choice for the window. The Overview pair is status. The old `POST /perc/boot/installed` and `POST /perc/boot/reinstall` stay valid. An unattended boot does not install.

2. **One guest at a time.** "Running" on this host means the RayNu-F guest this boot launches. The catalog is not a promise of N concurrent VMs.

3. **`linux_iso` is the type this firmware honors.** Alpine is the demo ISO already on the media. `windows_iso` stays on the form and is refused. `generic_uefi` and `linux_bzimage` are not this path.

4. **The datastore is RAYNU-SPARE.** The page shows that VD's byte size, the bytes the installed guest uses, and the free tail. UBUNTU0 and the H840 are outside the allocator.

5. **Slice 1 places only inside the existing window** (`PERC_IMAGE_BYTES`, 8 GiB). A requested disk larger than that window is refused, and the response carries `placeable_bytes`. The free tail is visible and is not a placeable disk yet. This slice does not add a format. A `linux_iso` that fits is the existing reinstall of the latched window. An empty latch does not become a fresh wipe target.

6. **Slice 2 places a new disk at the form's size in the free tail** and gives `vda` that geometry. That is the change that retires the 8 GiB cap. One writable disk of the allocated size. Guest LBA 0 of that disk is the first byte after the installed window. The window is not written. `vdc` stays hidden. A `linux_iso` of 8192 MiB stays the slice-1 reinstall of the window.

7. **Slice 3 stops feeding `setup-disk`** for a Guests-chosen `linux_iso` (window reinstall or a new tail disk). The guest still gets `root` at `login:`. The shell is the ISO's own prompt. Start of an already installed disk still withholds `setup-disk` and boots that disk. Choice 3 lived on `752586b9`: the ISO motd offered `setup-alpine`, then COM2 printed `boot: perc SPA linux_iso — setup-disk withheld`. The 8192 MiB window reinstall was not clicked on that boot.

8. **Outside Proven Core.** No doorbell. Do not format UBUNTU0. Do not erase `d43dbf07` to prove the page. GitHub Latest stays `v0.1.0-everest-closed`.

9. **Amendment (2026-09-29): the operator chooses the ISO on Guests, and the bytes live in a library on RAYNU-SPARE.** The slices are **M8.8.1** placement, **M8.8.2** upload, **M8.8.3** boot, and **M8.8.4** install and reclaim. M8.4's 256-byte host blob is not these slices. `EFI/RayNu/linux.iso` on the Cruzer remains the lab media for one F11. The product path is:

   - Guests offers a file button. The browser holds the operator's local ISO only long enough to send it.
   - The hypervisor stores those bytes unchanged in a reserved high region of RAYNU-SPARE. The region sits below the last-LBA mailbox probe. It does not overlap the 8 GiB window, a guest tail disk, UBUNTU0, or the H840.
   - Placeable shrinks by the bytes the library holds. A guest disk that would enter the library is refused.
   - The copy is chunked on the standing HTTPS session. The management reply buffer is 20 KiB. A distro ISO does not arrive as one POST body, and it is not held in the management arena.
   - Each stored file is a catalog row: name, ADR-014 type, size, and spare offset. Create uses the selected row as the CD and the Disk MiB field as `vda`.
   - `POST /iso/{id}/attach` stays the lab mock CD. It does not open a file and it does not write the spare. The M8.4 host blob (256 bytes, `UploadMode::HostReady`) is not this store. Firmware upload stays ESP-staged until COM2 shows a boot from the library.
   - Ingest does not patch the file. Unmodified media moves when COM2 shows `ISO-BOOT` of a library file whose kernel command line is that file's own line, with no `ISO serial console patched` line.
   - The first product file is `ubuntu-26.04-live-server-amd64.iso`. It is presented as a CD, with `console=ttyS0` added for that boot only. The stored bytes stay unchanged. The Alpine answerer stays quiet for this file.
   - The library file stays after the install. An 11-hour upload is not deleted when the installed disk boots. Guests **Clear ISO** (`POST /perc/library/clear`) detaches the CD, drops the catalog hold, and wipes the ISO signature sector so a later boot does not adopt the file. It does not scrub the rest of the bytes and it does not touch UBUNTU0, the 8 GiB window, or an existing tail such as `ee851fd5`. The installer reboot still has the CD until that click, which is the lesson of `67bdb0d9`.
   - **Amendment (2026-10-04): the file stays waiting until Guests chooses it.** Upload and adopt do not arm the CD. The list shows the 8 GiB Alpine, the 10 GiB Alpine, and the PERC ISO as row id 3 (`waiting`). The **ISO** button posts Disk MiB as `vda` and chooses the file. That choice publishes virtio `vdb` and makes RayNu-F read `\EFI\BOOT\BOOTX64.EFI` from the library El Torito. Start on an Alpine row does not attach the file. `27d4e540` had already armed the file at adopt, so `vdb` was the Ubuntu ISO while BlockIo `cd_bytes=1042284544` was still the Cruzer Alpine image.
   - **Amendment (2026-10-06): LoadedImage `FilePath` for that CD is the Media/FilePath node `\EFI\BOOT\BOOTX64.EFI`, not the CDROM device path.** Shim turns `FilePath` into a directory prefix and opens `grubx64.efi` there. `8822dbfa` had only the CDROM node, so the open was the FAT root and returned Not Found (`blk_rd=0`). A relative `File.Open` is resolved against the directory handle. M8.8.3 is not lived.
   - **Amendment (2026-10-08): `StartImage` appends `console=ttyS0` for the library CD only.** `87979e32` reached `RAYNU-V-RAYNU-F-EBS-OK` and Linux virtio `DRIVER_OK`. COM2 did not show `Linux version`. The stock kernel line has no serial console. The append is a new LoadOptions buffer for that boot. `LoadImage` does not clear the flag, so GRUB's buffer load of the kernel still receives it. Alpine disk boot does not. The stored file is not rewritten. M8.8.3 is not lived.
   - **Amendment (2026-10-08): the `linux` line is amended in the `grub.cfg` read view.** `6865b5ab` reached EBS and virtio `DRIVER_OK` with no kernel-line line and no `StartImage` line. GRUB 2.14 uses the EFI handover jump, so LoadOptions is not the command line the stub receives. `File.Open` of `grub.cfg` on the library CD builds a read view whose `linux` and `linuxefi` lines include `console=ttyS0`. `File.GetInfo` reports that longer size. The FAT bytes stay the stored file. A file that does not fit the view is read unchanged. Alpine disk boot does not build the view. M8.8.3 is not lived.
   - **Amendment (2026-10-08): that `linux` line is in the ISO9660 file GRUB reads with `BlockIo`.** `4e9ebcdb` reached EBS and virtio `DRIVER_OK` with no `grub.cfg` line. `blk_rd` fired while the menu was parsed. The El Torito FAT open never carried a `linux` line. On the library CD, a directory record named `grub.cfg` or `loopback.cfg` (ISO9660 or Joliet) has its Data Length raised when the file's last sector has room, and the extent read returns the line with `console=ttyS0`. The backing bytes stay the stored file. A file with no spare bytes in that sector is left unchanged and COM2 says so. Alpine disk reads are not amended. M8.8.3 is not lived.

   The first slice is packed when host tests place one ISO in the high region and refuse a guest disk that overlaps it. It is lived only after an iron upload and a boot from that offset. Scores stay put until then.

## Consequences

- Slice 1 Start lived on `5175b3da` (`choice=1`, `localhost:~#` on `d43dbf07`). The 10240 MiB refusal was not clicked on that EFI.
- Slice 2 is packed when the host tests pass. It is lived only after COM2 on a later EFI shows `choice=3`, `tail_off=8589934592`, and `[vda]` at the requested size. That boot must not be `5175b3da`. Scores stay put until then.
- Guests captions (`cap`, `note`) are fields on `GET /perc/guests`. The HTML shell prints those fields. The shell stays inside the 20 KiB HTTP reply (`webui_len()+256` ≤ `HTTP_RESPONSE_CAP`). Gzip of the shell waits until the shell itself is what grows. `b330e28f` put the sentences in the HTML and crossed that reply, so that EFI is not a flash.
- The list has two disk rows when a free-tail disk is known: id 1 is the 8 GiB window, id 2 is the tail disk. A complete library file is id 3, waiting, until Guests chooses it. Placeable shrinks by the disks and the file. Start on id 2 (`CHOICE_TAIL_BOOT`) boots it with `setup-disk` withheld and leaves the ISO waiting. Stop ends the running guest and leaves the page in the Stage 46 hold. Another Start needs a new hypervisor boot. No guest IP is published. After RayNu-F hands the VMCS to Linux, Stop is taken on that exit path. `f44ba647` stored Stop and never read it once Linux was up.
- Slice 1 is packed when the host tests pass. It is lived only after COM2 shows the Guests wait and a Start or a refused oversized disk on the R640.
- Slice 3 lived on `752586b9` choice 3. `ISO-BOOTX64`, `[vda]` 10.0 GiB, `localhost login: root`, ISO motd, then the withhold line. No scripted `setup-disk`. `ee851fd5` was mounted read-only, journal-recovered, and unmounted. Unmodified media 20→25. The ISO serial console is still patched. `root` is still typed. `f44ba647` still types `setup-disk` on a new `linux_iso`.
- Decision 9 is packed, not lived. `27357846` reserved `ubuntu-26.04-live-server-amd64.iso` (2,918,598,656 bytes) and accepted the first chunks. COM2 did not print `boot: M8.8 library CD stored`. The page poll shares the one TCP slot and the VM list replaces the counter. Do not click Upload again on that EFI. `6a7e72b1` unpacked the initrd (`Freeing initrd memory: 97388K`) and ran `/init`, then libc reported `CPU ISA level is lower than required`. The RAM tail is in the map (`bytes=2113929216 tail=1845493760`). `8c6bfa85` published `XCR0=0x2ff` and the same libc line came back. The CPUID filter cleared X2APIC (ECX bit 21) on every leaf, so userspace read vendor `GenuineIntEl` and glibc never read leaf 1. `1b01c2d8` showed userspace vendor GenuineIntel and `/init` reached systemd-udevd. `udevadm` then stuck in `synchronize_srcu` because Linux 7 starts that grace period with a local-APIC self-IPI and ICR writes were ignored. `6d630acc` injected `self-ipi vec=0xf6` four times. Casper mounted the live root. systemd printed `Welcome to Ubuntu 26.04 LTS!` and started the ttyS0 Subiquity getty. COM2 then showed `waiting for cloud-init`. No SRCU hung task. COM2 then sat on `waiting for cloud-init` with no guest NIC, and a rerun did the same. `9df8d68aa7ea` printed `CD grub.cfg console=ttyS0 ds=nocloud len=394->439` and the kernel line `console=ttyS0 ds=nocloud cloud-init=disabled`. The cloud-init units did not start. The tty stayed on `waiting for cloud-init`. This EFI appends `ci.ds=None`, `fsck.mode=skip`, `network-config=disabled`, and masks `casper-md5check.service` and `snapd.seeded.service` on that library `linux` line. The stored file stays. The language screen is not lived. M8.8.3 is not closed. The stored file is not rewritten. Subiquity has not started. M8.8.3 is not lived. Reclaim is `note_installed_disk_booted` and is not called from the disk-boot path yet. The Cruzer Alpine ISO remains that boot's other media. Attach CD remains the lab mock. Unmodified media stays 25. HDA stays 99% / 0.0 months. LOIHDA Bar B stays 60. The 2.9 TB VD is not the guest disk.
- ADR-014's type table is unchanged. This ADR owns the boot policy, the datastore, and the ISO library. ADR-018 M8.4 names the upload milestone; the spare library is the iron destination.

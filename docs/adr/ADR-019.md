# ADR-019: PERC RAID virtual disks are the R640 fleet datastore

- **Status:** Accepted
- **Date:** 2026-09-13
- **Pillars:** [D] Dell-native · [Z] single binary · [A] audit (guest disks must survive HV reboot)
- **Parent:** [ADR-018](ADR-018.md) (M8 persist) · [ADR-005](ADR-005.md) (iDRAC tiers — health, not I/O) · [ADR-004](ADR-004.md) (EPT exclusive ownership)
- **Does not change:** Everest closed (ADR-018). Proven Core boundary (ADR-002). Lab rule: do not format the Ubuntu standing VD on this R640.

## Context

RayNu-V’s commercial claim is **extending the life of existing Dell PowerEdge R640 / R650 / R660 fleets** — replace the licensed hypervisor, keep the iron.

Those fleets almost always keep guest and boot disks on **PERC RAID virtual disks** (H740P Mini / MegaRAID SAS-3 `1000:005D`, PCI class `01:04`). A product that can persist only to:

- leftover DRAM (dies on Force Off),
- a USB stick, or
- a spare NVMe that most RAID-configured R640s do not expose as class `01:08`,

is a **lab hypervisor**, not a fleet product. USB DurableLun (M8.0 mechanism) is still required tonight: it proves Force Off persist on media we already speak. It does **not** close “we can replace ESXi on the disks you already paid for.”

ADR-005 **Tier 2** is PERC **health via OEM Redfish**. That is telemetry. It is **not** a MegaRAID I/O path. “Never block a milestone on Tier 2” still applies to OEM health schemas. It does **not** mean the fleet SKU can ship without RAID virtual disks.

Current mapper (`mgmt/durable_lun.rs`) **classifies** RAID and prints `skip PERC`. That remains correct for **this lab box**: the PERC VD is Ubuntu (`raynuvsrv1`), standing boot, flash host. Product I/O must target a **dedicated VD** (spare array, unused capacity, or a box that is no longer dual-boot), never the Ubuntu root.

## Decision

1. **Fleet datastore target is PERC RAID virtual disks** (and NVMe when the chassis actually has class `01:08`). USB DurableLun is **lab/mechanism only**. It is not the product SKU.

2. **Split M8.0 into two closes** (order: mechanism, then fleet media):

   | Close | Marker | Media | Meaning |
   |-------|--------|-------|---------|
   | M8.0-mech | `RAYNU-V-M8-DISK-PERSIST-OK` | NVMe or USB ≥ 1 GiB (not ESP Cruzer) | Force Off persist **mechanism** on iron |
   | M8.0-perc | `RAYNU-V-M8-PERC-LUN-OK` | A PERC **virtual disk** that is not Ubuntu | Fleet SKU: virtio-blk on a RAID VD survives Force Off |

   Host/CI never print either iron marker. Nested QEMU ≠ R640. USB persist ≠ PERC persist.

3. **I/O, not census.** Census already reads RAID class. The work is post-EBS MegaRAID: identify VDs, Read/Write, back virtio-blk / RayNu-F BlockIo the same way NVMe/USB do. UEFI firmware BlockIo on the PERC dies at ExitBootServices — PRE-EBS RAID BlockIo does not count.

4. **Outside Proven Core.** MegaRAID stays in `mgmt/` / `devices/` unless a future ADR expands the boundary (default **no**). ADR-004 still holds: VD HPAs are virtio/BlockIo only; guests never see the RAID card as RAM.

5. **Do not format the lab Ubuntu VD.** Product PERC work uses a spare VD, unused disks in a new VD, or a dedicated R640. Standing boot on `raynuvsrv1` stays Ubuntu until that VD exists.

6. **Living plan:** [`docs/m8_plan.md`](../m8_plan.md). HDA names PERC as the fleet persist residual. USB iron tonight still proceeds ([`m8_persist_iron.md`](../runbooks/m8_persist_iron.md)).

## Consequences

- Skipping PERC is no longer “product policy.” It is **lab safety** until M8.0-perc.
- NVMe remains a valid SKU where the customer actually has NVMe. It is not a substitute for RAID fleets.
- AHCI remains skipped until a later ADR (PCH SATA is not the R640 fleet default).
- A Linux `megaraid_sas`-shaped mailbox driver is the self-sufficient bet. Dell partnership can accelerate firmware docs; it is not a wait-gate to *start*.
- Size budget (ADR-003) still applies; a RAID driver is not an excuse to blow 20 MB.
- Iron rollback for Everest remains [`v0.1.0-everest-closed`](https://github.com/vikkp/RayNu/releases/tag/v0.1.0-everest-closed). Do not F11 a PERC prototype as the known-good.

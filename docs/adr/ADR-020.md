# ADR-020: RayNu VM Generation 1

- **Status:** Accepted as the direction. Not built past a patched Alpine reboot-to-disk.
- **Date:** 2026-10-04
- **Pillars:** [Z] single binary · [V] architecture (RayNu-F stays outside the Proven Core)
- **Parent:** [ADR-016](ADR-016.md) (RayNu-F) · [ADR-017](ADR-017.md) (F7) · [ADR-014](ADR-014.md) (typed ISO)
- **Does not change:** Proven Core boundary (ADR-002). Guest SSH is [ADR-013](ADR-013.md) Appendix C, after this plan's install, not inside it.

## Context

ADR-016 decided that RayNu-F is the guest firmware. The F0–F7 record in that ADR is how a **patched Alpine** ISO reached `RAYNU-V-RAYNU-F-DISK-BOOT-OK` on iron (2026-09-10). The LOI work since then stored an unmodified Ubuntu ISO on the spare (M8.8.2, `93088c32`) and did not boot it.

Two facts the generation has to keep:

1. **RayNu-F is host-side firmware.** The guest sees UEFI 2.10 tables. Every service entry is a trampoline (`out 0x5246`) into `raynu_f/services.rs`, a host-tested dispatcher. OVMF, Hyper-V UEFI, and ESXi firmware run inside the guest. There is no firmware image in the guest to corrupt. That is what makes a spec on the interface plausible. Keep it. Runtime services are harder because of it: after `ExitBootServices` the OS calls them at guest-virtual addresses under its own page tables.

2. **Nothing Alpine-specific lives in `raynu_f/`.** The Alpine debt is elsewhere:
   - `mgmt/iso_install.rs` still patches `grub.cfg` with `console=ttyS0`, `earlycon`, `lpj=4194304`, `no_timer_check`, `tsc=reliable`, `clocksource=tsc`, `idle=poll`, `initcall_blacklist=piix_init`, `efi=noruntime`, and `usbdelay=30`. Each knob is a platform hole with a name.
   - `devices/guest_serial_answer.rs` still answers the Alpine installer.
   - `vmx/guest_uefi.rs` is the device model that grew up around OVMF puppeting. The RayNu-F Linux exit path still inherits that model.

The honest line today: a host-side UEFI boot-services implementation that boots a patched Alpine ISO. The product line this ADR accepts: **RayNu VM Generation 1**, one specified virtual machine (devices, ACPI, CPUID, and the firmware contract) that boots unmodified OS media.

## Decision

One firmware, many guests. No per-distro forks. OVMF is an oracle, not the product. The moat is the hypervisor. The firmware has to become boring. The analog is Hyper-V Generation 2, not an ESXi hardware-version matrix: UEFI only, no legacy devices, synthetic devices only. Guests that need otherwise are rejected, not patched.

1. **The bar is unmodified media, and it is measurable.** A stock ISO boots to its installer, installs, and reboots to its own disk, with zero patching and zero auto-answer. Each knob in the patcher is retired by fixing the platform. The patcher is not how a new distro gets in.

2. **Runtime services are in v1.0.** `GetVariable` / `SetVariable` / `GetNextVariableName`, `GetTime`, `ResetSystem`, and an honest `SetVirtualAddressMap` with guest-virtual translation through the guest CR3. Today `GuestMem` is an identity slab and `GetVariable` returns not-found. Windows will not boot without runtime services. Ubuntu and RHEL installers boot on this tree only when the kernel is given `efi=noruntime`, which cannot be injected into unmodified media. `efi=noruntime` is a lab flag, not a generation bit.

3. **Firmware and the device model are one contract.** RayNu-F v1.0 is not specified without RayNu VM Generation 1. GRUB and the kernel see both. Publish them as one document and version them together.

4. **RayNu-F stays outside the Proven Core** (ADR-002). It is the best-shaped candidate for later L2 specs on an interface: `AllocatePages` non-overlap, memory-map consistency, `ExitBootServices` map-key monotonicity, `BlockIo` bounds, and GVA translation bounds once runtime services exist. Promotion, if ever, is one small module by a new ADR, inside the Proven Core LOC buffer. This ADR does not promote it.

### Phases

No dates. A phase is open until its exit line is on a log or in CI. Host tests do not close a guest phase.

| Phase | Work | Exit |
|---|---|---|
| **0** | Land F7, then stop adding Alpine glue. | Nested reboot-to-disk on RayNu-F. The patcher and the auto-answer are frozen behind a lab feature. No new guest-side patching on the product path. |
| **1** | Retire OVMF as the product and split the monolith. `vmx/guest_uefi.rs` becomes the exit loop, a Gen-1 device model (one module and test per device), and `raynu_f/`. Delete the OVMF launch and puppeting code. The do-not-F11 history stays in an ADR appendix. | Alpine E5 still passes on the split. `guest_uefi.rs` is gone. |
| **2** | Gen-1 devices, defined by retiring knobs. Remove PIIX IDE/ATAPI (`initcall_blacklist=piix_init`). The ISO RayNu-F already reads via `BlockIo` is a virtio-blk disk for Linux (`00:03.0` is that shape). Correct the timers so `no_timer_check`, `lpj=`, `tsc=reliable`, `clocksource=tsc`, and `idle=poll` are unnecessary. Decide the console once: headless serial, or a GOP linear framebuffer (recommended for v1.0, because GRUB and the installers assume it). Clean CPUID: hypervisor bit, a RayNu leaf at `0x40000000`, topology, no host leakage. ACPI: FADT reset, MADT, HPET or an explicit absence, MCFG, `_PRT`. SMBIOS types 0/1/3/4/16/17. Virtio-pci modern only: blk, net, console, rng. No legacy virtio, no e1000. | A stock Alpine extended ISO boots to `login:` with the `grub.cfg` as shipped. The patcher is deleted. |
| **3** | Firmware for real OS loaders. Variable store (`BootOrder` / `Boot####`, persisted per VM). `ResetSystem`. Runtime services with GVA translation and `SetVirtualAddressMap`. Device-path `LoadImage` (shim to GRUB). `Exit` / `UnloadImage`. `GetTime` from a virtual RTC. A trace of every service call: a new ISO fails as `UNSUPPORTED at RT.GetVariable`, not as a hang. | Ubuntu Server and Debian netinst boot unmodified to their installers. `efi=noruntime` is absent. |
| **4** | Freeze v1.0 in `docs/raynu_vm_gen1.md`. CPUID policy, memory map, PCI BDFs, ACPI/SMBIOS, each protocol marked implemented or `UNSUPPORTED` by contract, console policy, and the explicit refusals (CSM, legacy virtio, IDE, runtime-less mode). VM config carries `generation = 1`. | CI conformance: Alpine extended, Ubuntu Server, Debian netinst, Rocky boot ISO. Each installs, reboots to disk, and reaches a login. |
| **5** | After v1.0, not blockers. Secure Boot, vTPM, firmware-phase SMP, HTTP/PXE, Windows, UEFI SCT as an external oracle. | Not a v1.0 exit. |

### What stops

No new guest-side patches on the product path. No per-ISO stanzas added to `iso_install.rs`. No `efi=noruntime` as a supported mode. No distro is called supported until it passes unmodified. OVMF puppeting is not resumed to close a gap.

## Consequences

- **Phase 0 is only half closed.** Iron F7 reboot-to-disk lived for patched Alpine (`RAYNU-V-RAYNU-F-DISK-BOOT-OK`). The patcher and `guest_serial_answer` are still on the product path. The "stop adding Alpine glue" half of the exit is open.
- **Phases 1–5 are not started.** `vmx/guest_uefi.rs` is still the monolith. `GetVariable` is still not-found. `SetVirtualAddressMap` is still unsupported, which is why the Alpine line carries `efi=noruntime`.
- **M8.8.2 is unmodified bytes, not this plan's boot.** `93088c32` stored `ubuntu-26.04-live-server-amd64.iso` unchanged. M8.8.3 (boot that file, add `console=ttyS0` for that boot only, no rewrite of the stored bytes) is the first product step that meets Phase 2's console rule and Phase 3's installer bar. It has not been run.
- **Guest SSH is not this ADR.** A virtio NIC with its own MAC, leaving through BCM5720 `01:00.1` / `b0:26:28:5c:5a:39`, is [ADR-013](ADR-013.md) Appendix C. The SPA stays on `:38`. That slice is after an installed disk exists.
- Scores stay put. A patched Alpine login is not an unmodified-media close.

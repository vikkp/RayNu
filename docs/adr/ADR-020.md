# ADR-020: Two queues after Everest — operator (M8) vs RayNu VM Generation 1

- **Status:** Accepted
- **Date:** 2026-09-13
- **Pillars:** [Z] single binary · [D] Dell-native · [A] audit ([V] architecture preserved — no Proven Core expansion)
- **Parent:** [ADR-018](ADR-018.md) (M8 operator) · [ADR-019](ADR-019.md) (PERC fleet datastore) · [ADR-016](ADR-016.md) (RayNu-F) · [ADR-014](ADR-014.md) (typed ISO) · [ADR-017](ADR-017.md) (F7 reboot-to-disk)
- **Does not change:** Everest closed (ADR-018). Proven Core boundary (ADR-002). Size budget (ADR-003). Lab rule: do not format the Ubuntu standing PERC VD. Iron rollback remains [`v0.1.0-everest-closed`](https://github.com/vikkp/RayNu/releases/tag/v0.1.0-everest-closed).

## Context

Mount Everest closed on iron (`f72b4276` / `--run 34552377351`). Two different kinds of leftover work then landed in the same “next” slot, and agents started fighting:

| Queue | Question | Living plan |
|-------|----------|-------------|
| **M8 operator** | Where do disks and the operator live? Persist across HV reboot, TLS, auth, console, ISO upload, catalog. | [`docs/m8_plan.md`](../m8_plan.md) |
| **RayNu VM Generation 1** | What is the guest allowed to be? One specified VM (devices + ACPI + CPUID + firmware). Unmodified media. | [`docs/gen1_plan.md`](../gen1_plan.md) |

Without a written split, a later agent can honestly believe any of these is “the next commit”:

- Delete `mgmt/iso_install.rs` `patch_iso_linux_serial_console` and `devices/guest_serial_answer.rs` because Gen-1 forbids guest-side patches.
- Start M8.1 TLS because ADR-018 lists it after persist, while iron Force Off persist is still open.
- Treat Windows as a peer of TLS because ADR-018 numbered it **M8.6**.
- Format the lab Ubuntu PERC because ADR-019 says RAID is the product target.
- Reopen Everest because the Alpine ISO is still patched.
- Claim `raynu_f/` is missing / `ISO-INSTALL-OK` is still open (stale talk-only paste — **false** on lived `main`).

Those are not product disagreements. They are **queue collisions**. This ADR is the contract so agents do not “freak out.”

### Lived honesty (do not use stale paste)

On lived `origin/main` (Everest-closed + M8 catch-up):

- **RayNu-F is the product path.** `raynu_f/` exists. ADR-016 is in force.
- Iron printed `RAYNU-V-M7-ISO-INSTALL-OK` and `RAYNU-V-RAYNU-F-DISK-BOOT-OK`. Everest is **closed**.
- Nested persist `RAYNU-V-M8-DISK-PERSIST-NESTED-OK` closed on `raynuvsrv1` (`ce3d8a09`). Nested QEMU ≠ R640.
- **Phase 0 nested reboot-to-disk landed.** Iron still uses the ISO patcher + serial auto-answer. That is **Phase 2 still open**, not “Everest unfinished.”
- `vmx/guest_uefi.rs` is still huge (exit loop + Gen-1 devices mixed). That is **Phase 1 still open**.

Ignore any plan text that says “on this checkout `raynu_f/` is not present” or “ISO-INSTALL-OK still open.”

## Decision

1. **Two queues, one binary.** M8 is where disks and the operator live. Gen-1 is what the guest is allowed to be. Both compile into `r640-hypervisor.efi`. Neither queue reopens Everest. Cluster stays **M9**.

2. **Serialized closes** (design overlap is allowed; **closing** out of order is not, unless this ADR and the living plans are rewritten):

   | Order | Close | Marker / meaning | Notes |
   |-------|-------|------------------|-------|
   | **1 (NOW)** | **M8.0-mech** | `RAYNU-V-M8-DISK-PERSIST-OK` | USB ≥ 1 GiB (not Cruzer) or NVMe `01:08`. Keep patched Alpine + auto-answer. Do not F11 until COM2 `I/O ready` + virtio on the LUN. |
   | **2** | **M8.0-perc** | `RAYNU-V-M8-PERC-LUN-OK` | Spare PERC VD, not Ubuntu. [ADR-019](ADR-019.md). Design may overlap (1); does not close before (1). |
   | **3** | **Gen-1 Phase 1** | Split `vmx/guest_uefi.rs` (exit loop / Gen-1 devices / `raynu_f/`) | OVMF = `tools/` oracle only. After (1). |
   | **4** | **Gen-1 Phase 2** | Delete ISO patcher + auto-answer | Unpatched alpine-extended → login. **Do not delete the patcher before (1).** Prefer after Phase 1. |
   | **5** | **M8.1 + M8.2** | TLS, then real auth | Design overlap OK; do not **close** before (1). Do not start product TLS until persist is on COM2 unless `m8_plan.md` is rewritten. |
   | **6** | **M8.3** | SPA guest console | After (1). Serial already installed Alpine. |
   | **7** | **Gen-1 Phase 3** | Runtime services v1.0 + GVA + `SetVirtualAddressMap` | Unmodified Ubuntu/Debian. `efi=noruntime` is lab, not supported. After Phase 2. |
   | **8** | **M8.4 / M8.5** | ISO upload, UEFI catalog persist | After (1). |
   | **9** | **Gen-1 Phase 4** | Freeze `docs/raynu_vm_gen1.md`, `generation = 1`, CI matrix | Do not pretend this freeze exists today. |
   | **10** | **M8.6 / Gen-1 Phase 5** | Windows / Secure Boot / vTPM later | **After** the Gen-1 freeze. Windows is **not** a peer of TLS. |
   | **11** | **M9** | Cluster / vMotion-like | After operator hardening. Not a persist substitute. |

3. **Overlap rule.** An agent may *design* MegaRAID, TLS, or the `guest_uefi.rs` split while M8.0-mech is in flight. It must not:

   - flash a persist prototype as the known-good,
   - print iron markers from host/CI/nested,
   - delete the Alpine patcher / auto-answer to “help” Gen-1 before M8.0-mech,
   - close M8.1 TLS, M8.0-perc, or Phase 2 before M8.0-mech COM2 exists.

4. **RayNu-F standing architecture** (product, not a talk-only note):

   - Host-side firmware. Guest sees UEFI 2.10 tables; services trampoline `out 0x5246` into Rust `dispatch` over `GuestMem`.
   - Product is **RayNu VM Generation 1**: one specified VM (devices + ACPI + CPUID + firmware), Hyper-V Generation 2 style (UEFI-only, no legacy BIOS, synthetic only). Unmodified media. Reject guests that need more; do not patch them **as the product path**.
   - Conformance (Phase 2+): stock ISO → install → reboot → login; **zero** guest-side product patches; **zero** auto-answer. Alpine knobs (`patch_iso_linux_serial_console`, serial auto-answer, `efi=noruntime`) are a **burndown**, not a feature.
   - Runtime services are **v1.0**, not “later.” `efi=noruntime` is lab until Phase 3.
   - RayNu-F stays **outside** Proven Core. Promotion only by a new ADR into the ~3k LOC buffer (default **no**).

5. **Stops (agent contract — do these and you are wrong):**

   - Guest-side **product** patches (new per-ISO stanzas, new `initcall_blacklist`, new Alpine-only cmdline).
   - OVMF puppeting as the product path after Phase 1 (OVMF may remain a `tools/` oracle).
   - Claiming a distro until an **unmodified** ISO installs.
   - Claiming Gen-1 Phase 4 frozen.
   - Treating leftover DRAM, nested File, USB DurableLun, NVMe, and PERC as the same persist close.
   - Printing `RAYNU-V-M7-ISO-INSTALL-OK`, `RAYNU-V-M8-DISK-PERSIST-OK`, or `RAYNU-V-M8-PERC-LUN-OK` from host, CI, or nested QEMU.
   - Formatting the Ubuntu PERC on `raynuvsrv1`.
   - Putting MegaRAID, TLS, or RayNu-F into the Proven Core without a new ADR.
   - Starting M9 cluster / vMotion on the M8 path.
   - Reopening Everest because the patcher still exists.

6. **Windows is Phase 5, not an M8.6 peer of TLS.** ADR-018’s M8.6 row remains the operator-facing name for “Windows / multi-distro later.” This ADR **orders** it: after Gen-1 freeze (Phase 4), not beside M8.1. ADR-014 typed ISO stays the image contract.

7. **Living docs + always-on rule.** Plans: [`docs/m8_plan.md`](../m8_plan.md) (operator) and [`docs/gen1_plan.md`](../gen1_plan.md) (firmware/guest). Agent rule: [`.cursor/rules/m8-gen1-queues.mdc`](../../.cursor/rules/m8-gen1-queues.mdc). HDA overall stays **99%**. `months_to_everest` stays **0.0**.

## Consequences

- ADR-018 decision 2 (M8.1…M8.6 list) is **still the operator table**. This ADR adds the Gen-1 queue and the close-order lock against the patcher/TLS/Windows collisions.
- Keeping the ISO patcher tonight is **compliant**, not a regression. Deleting it before M8.0-mech is the regression.
- Census `skip PERC` remains lab safety ([ADR-019](ADR-019.md)), not “RAID is out of scope.”
- A future agent that finds two “next” items must cite this ADR’s order table, not pick the more exciting one.

# ADR-012: UEFI NIC HTTP Listen for Everest E3

- **Status:** Accepted
- **Date:** 2026-08-15
- **Pillars:** [Z] [D] [A] (Proven Core **unchanged** — outside unless a future ADR expands ADR-002)
- **Parent:** [ADR-009](ADR-009.md) (Mount Everest E3) · size: [ADR-003](ADR-003.md) · iDRAC: [ADR-005](ADR-005.md)

## Context

ADR-009 defines Everest **E3 — Network UI**: a browser on the operator LAN
must reach the SPA + REST, not merely in-process / host-loopback dispatch.

M7.1 already closed on Latitude with:

- In-binary HTTP/1.1 codec + Bearer auth (`mgmt/http.rs`)
- Host `TcpListener` proof (`mgmt/http_listen.rs`)
- Firmware entry `listen_mgmt_http_uefi` returning `UnsupportedOnFirmware`

M7.2–M7.4 host-smoked datastore / ISO / create-VM UI against that codec.
M7.5 / E2 (real R640 boot) is the prior hard gate (see
`docs/evidence/r640/` / `RAYNU-V-R640-BOOT-OK` when closed).

**Residual:** while the R640 runs RayNu-V, a laptop on the same LAN still
cannot open the already-shipped SPA. That blocks honest E3 and makes E4/E5
iron testing Latitude-only. ADR-009 left the firmware bind as
“Tcp4/SNP (or equivalent)” without locking the stack, TLS posture, NIC
selection, or acceptance markers.

This ADR locks those implementation choices for the **next build focus**.

## Decision

1. **Goal (E3 MVP):** From an operator laptop on the management LAN, open
   `http://<r640-mgmt-ip>:8443/` (default port =
   `MGMT_HTTP_DEFAULT_PORT`) against a **running** `r640-hypervisor.efi` on
   real PowerEdge R640 (or QEMU+OVMF with a real virtio/e1000 user-net path
   for lab), load the SPA, and complete at least one Bearer REST exchange
   (e.g. `GET /vms`). Host-loopback alone does **not** close E3.

2. **Stack — UEFI `Tcp4` protocol (preferred), SNP as fallback substrate.**
   - Primary implementation uses the UEFI **TCP4** protocol service on an
     already-started managed network interface (DHCP or static via firmware /
     iDRAC shared LOM as available).
   - If TCP4 is unavailable on a target firmware build, **SNP** (Simple
     Network Protocol) plus a minimal in-tree TCP may be used — but only as a
     documented residual with a size audit (ADR-003). Do not ship two full
     stacks.
   - Reuse the existing `handle_http_request` codec; do not fork a second
     HTTP implementation.

3. **In-binary only ([Z]).** No out-of-band “helper” OS process, no sidecar
   container, no second binary that serves the UI. The listener lives in
   `r640-hypervisor.efi` under `mgmt/` (outside Proven Core).

4. **Plaintext HTTP first; TLS deferred.** Matches ADR-009 M7.1 lab note.
   First iron accept is HTTP. TLS (or HTTPS redirect) is a follow-on under
   the ADR-003 size budget and does **not** block the E3 MVP marker below.
   Document the lab threat model: management LAN / iDRAC isolated network,
   not Internet exposure.

5. **NIC / bind policy.**
   - Bind `0.0.0.0:<port>` on the first usable UEFI IPv4 interface that has a
     completed DHCP (or static) configuration.
   - Prefer the **host onboard / shared LOM** path the operator uses for OS
     install networks; do not require a dedicated second NIC for MVP.
   - Print the bound IPv4 + port on COM1/COM2 (and audit ring) so iDRAC SOL
     operators can copy the URL without guessing.
   - If no IPv4 interface is ready after a bounded wait, emit a clear serial
     residual and keep HV guest path alive (listen failure must not panic the
     hypervisor).

6. **Gate numbering — new slice M7.6**, do not reopen `GAP(CLOSED M7.1)`.
   - Host/CI may keep proving the codec + stub/surface.
   - New iron (and QEMU net) marker:
     ```text
     RAYNU-V-M7-UEFI-HTTP-OK
     ```
   - Optional host scaffold while wiring:
     ```text
     RAYNU-V-M7-UEFI-HTTP-SCAFFOLD-OK
     ```
   - Closing E3 in HDA additionally requires a **browser-reachable** proof
     recorded in evidence (screenshot or curl transcript + serial bind line)
     against real R640 when claiming Mount Everest E3 DONE.

7. **Proven Core.** HTTP listen, NIC bring-up, and DHCP client remain
   **outside** Proven Core (ADR-002 / ADR-009). No Verus obligation for M7.6
   unless a future ADR expands the boundary.

8. **Size.** Listener + TCP4/SNP glue must keep the release `.efi` under the
   ADR-003 hard limit (20 MB). Prefer UEFI protocols over embedding a full
   TCP/IP stack. Run `./tools/check-size.sh` on every M7.6 PR.
   **Lived (2026-08-16):** R640 Virtual Floppy + ConnectController yields
   `snp>0` / `tcp4=0`. SNP residual uses **smoltcp** (DHCP + TCP) under
   `uefi-bin` only — ~+44 KiB observed, still under ADR-003 target. Tcp4
   remains preferred when present; do not run two stacks on the same path.
   **Root cause (iron 2026-08-16):** after PCI+SNP+all-handles, Dell
   publishes PXE/HTTP/Ip4Config2 (`pxe=8 http=4 ip4cfg=4`) but **never**
   `Tcp4ServiceBinding` (`mnp=ip4=dhcp4=tcp4=0`). Vendor closed stack —
   firmware Tcp4 listen is a **platform limitation** on Virtual Floppy.
   See `docs/evidence/r640/2026-08-16-uefi-tcp4-absent-root-cause.md`.
   SNP residual unchanged and still prints `RAYNU-V-M7-UEFI-HTTP-OK`.

## Alternatives considered (rejected)

| Alternative | Why rejected |
|-------------|--------------|
| **Leave `UnsupportedOnFirmware` and claim E3 via Latitude host TCP** | Violates ADR-009 E3 (“not host-only dispatch”) and blocks iron E4/E5. |
| **Split helper binary / Linux userspace proxy on a second OS** | Breaks pillar **[Z]** single-binary; splits attestation surface. |
| **TLS-first before any listen** | Size/complexity; ADR-009 already deferred TLS for M7.1. HTTP MVP unblocks iron sooner. |
| **Embed lwIP (or similar) as primary stack** | Larger binary risk; prefer firmware Tcp4. Allowed only as SNP residual with explicit size ADR note. |
| **iDRAC HTML5 console as the “network UI”** | Wrong surface — E3 is the RayNu-V SPA/REST on the host NIC, not BMC KVM. |
| **Reopen / rewrite M7.1 GAP** | M7.1 host codec path is honestly closed; firmware bind is a new residual → M7.6. |
| **Expand Proven Core to cover HTTP** | Out of scope; no isolation theorem dependency for listen. |

## Acceptance markers

### Scaffold (host / CI — does not close E3)

```text
RAYNU-V-M7-UEFI-HTTP-SCAFFOLD-OK
```

Present when: runbook + `listen_mgmt_http_uefi` surface + tests exist; firmware
may still stub. Must **never** print the iron OK marker from Latitude-only smoke.

### Implementation / lab net (QEMU+OVMF or Latitude with real listen)

```text
RAYNU-V-M7-UEFI-HTTP-OK
```

Minimum:

1. `listen_mgmt_http_uefi` no longer returns `UnsupportedOnFirmware` on the
   supported path (or returns success after bind).
2. Serial shows bind line: mgmt HTTP listening on `a.b.c.d:8443` (or chosen port).
3. From another host namespace / laptop: `GET /` returns SPA bytes; `GET /vms`
   (or documented Bearer route) returns a codec-valid response.
4. `./tools/check-size.sh` green; ADR-003 limit held.
5. `GAP(CLOSED M7.6): UEFI NIC HTTP listen` recorded in `mgmt/` gate module.

### Everest E3 (HDA)

E3 flips **DONE** only when the OK marker is reproduced on **real PowerEdge
R640** with operator-LAN browser (or equivalent curl) evidence filed under
`docs/evidence/` (or paper §6). QEMU alone is insufficient for HDA E3 DONE
(same honesty rule as E2 / ADR-009).

## Consequences

- Next Everest-path build focuses on `mgmt/http_listen.rs` + UEFI net bring-up,
  not ISO/El Torito, until M7.6 lab OK is green (ISO remains E5 parallelizable
  after listen exists on iron).
- Update [`docs/m7_plan.md`](../m7_plan.md) with an **M7.6** section; HDA P0 /
  Summit C residual cites this ADR.
- M7.1 stays closed; docs must say “UEFI listen residual → ADR-012 / M7.6”.
- TLS, IPv6, multi-NIC bonding, and HTTPS-only policy are explicit non-goals
  for M7.6 MVP.
- Failure to obtain DHCP must be a soft residual (serial WARN), not a boot
  deadlock — guest SHELL / M4 path remains usable via COM2.

## Amendment (2026-08-16) — post-EBS SNP residual

E3 MVP closed PRE-EBS (`RAYNU-V-M7-UEFI-HTTP-OK`). Firmware Tcp4 on this boot
method is a **platform limitation** (do not chase). Durable management HTTP
after ExitBootServices was attempted by parking SNP + smoltcp:

- Leak/park the protocol before EBS (no CloseProtocol).
- Do not `locate_handle` / `stall` after EBS (TSC delay).
- Soft-fail if UNDI is dead; PRE-EBS window stays the fallback.
- Iron marker `RAYNU-V-M7-POST-EBS-HTTP-OK` is firmware-only after a post-EBS
  HTTP exchange. Host/CI prints only `RAYNU-V-M7-POST-EBS-HTTP-SCAFFOLD-OK`.
- Size still ADR-003. TLS / El Torito / Redfish wait until this listen works.

## Amendment (2026-08-17) — firmware SNP dead after EBS

Iron on Cruzer (BIOS 2.2.11):

1. First `iface.poll` immediately after ExitBootServices **never returned**
   (`smoke frame` hung).
2. Skip-immediate-poll: guest path green, then idle SNP after `BOOT-OK` —
   Mac curl to the parked lease timed out; Dell UEFI RSOD (invalid opcode,
   RIP=`0x17`).

**Decision:** do not call firmware SNP Transmit/Receive after EBS. After
VMXOFF print WARN and return. PRE-EBS remains the **bring-up** management
UI (Everest **E3** MVP). Lifetime HTTP after EBS is **not** an ADR-012
extension.

**Superseded for post-EBS:** the 2026-08-16 “park SNP and resume listen”
residual. Durable management network architecture is **[ADR-013](ADR-013.md)**
(Proposed): host-owned NIC + smoltcp, HDA **E3b**, marker
`RAYNU-V-M7-HOST-NIC-HTTP-OK` when an exchange lands after `BOOT-OK`.
Do not chase SNP or Tcp4 after EBS. Evidence:
`docs/evidence/r640/2026-08-17-post-ebs-snp-dead.md`.

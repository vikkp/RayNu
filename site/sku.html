RayNu-V

If you signed today

What this letter holds

A non-production letter for one dedicated-box PowerEdge. You would be holding one EFI, a browser on that box, and an Ubuntu 26.04 guest that has already reached vikkp@raynusrv2 on a 10 GiB tail of the spare. The older disk that comes back after a chassis power-off is an 8 GiB USB window. The page is TLS 1.2 HTTPS with a lab millicert. The first minutes of boot are still plaintext HTTP. The door is a lab latch until auth.token is on the stick.

In your hands

On that one box

  • One file, r640-hypervisor.efi. No second operating system to install. No package set.
  • On a real PowerEdge you can dedicate, the loop has already happened: open the page, start a Linux install, reboot onto the installed disk, and reach a login:.
  • The guest you can log into is Ubuntu 26.04, vikkp@raynusrv2:~$, on a 10 GiB tail of the spare. That login has been repeated (c3a70e62, and again on the serial console at 33c9b141). The rest of the 2.9 TB virtual disk is outside this letter. Leave the 400 GB boot disk, UBUNTU0, alone.
  • The disk that has come back after Force Off is the older 8 GiB USB window on a Toshiba stick. You get that window, not the whole stick, and not memory that vanishes when the hypervisor reboots.
  • You open the page at https://10.99.99.x:8443/. The certificate is a lab millicert. The cipher is TLS 1.2. RAYNU-V-M8-TLS-OK printed on 928d6224 after curl --cacert returned the page, and the page stayed up on 1f33eeda. Before boot finishes, that same port is plaintext HTTP.
  • You enter with the shared lab latch raynu-v-bringup, until EFI/RayNu/auth.token is on the stick. That string is what the box accepts today.
  • The page has typed into an Alpine guest once (abc). The Ubuntu login you can repeat is on COM2 ttyS0. The guest log still mixes host lines. This is not a remote desktop. iDRAC remains how you watch the console.

Outside the signature

What you would be declining

  • not PERC fleet. You are not taking the array. A 10 GiB tail of the spare holds Ubuntu. The rest of the 2.9 TB virtual disk stays hidden. The second controller stays closed. The USB window is a different disk. Leave UBUNTU0 alone.
  • not a guest LAN. The Ubuntu shell is up. It has no working network interface. No packet from that guest has left the second port. An interrupt-pin change is in test. It is outside what you would be signing for today.
  • not cluster. No move of a running guest between boxes, no placement across a fleet, no hot-add. Those belong to a later letter.
  • not Windows. Ubuntu 26.04 and Alpine have both reached a login. Windows is a later letter.
  • The HTTPS you could show is the lab millicert and one TLS 1.2 cipher. The boot window is still plaintext HTTP.
  • There is no operator account yet. The lab latch is the credential the box accepts.
  • The page typed into Alpine once. It is not a remote desktop. Chassis power is the iDRAC control.

Which letter

The one on the table

The letter you could sign today is the dedicated-box letter: one PowerEdge you can afford to set aside. The other letter — keep the servers, replace the hypervisor on the disks you already own — is a different signature. A USB stick that comes back after power-off is the first letter. It is not the second.

The install loop, the USB window, this page, and HTTPS are in the first letter. The page stayed up. A keyboard from the page reached Alpine once. An operator password is still open. Ubuntu on a 10 GiB spare tail is a step toward the second letter. The whole virtual disk stays hidden. A guest LAN is not in either letter yet.
